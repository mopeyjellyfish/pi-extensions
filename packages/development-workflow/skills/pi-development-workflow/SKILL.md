# Pi Development Workflow

Use this skill for non-trivial features and fixes that need durable decisions and evidence. Read [references/philosophy.md](references/philosophy.md) when shaping a pitch, planning slices, or reviewing design quality; it defines the sourced agent-native Shape Up adaptation behind these rules. When pi-subagents is available, read [references/model-routing.md](references/model-routing.md) before delegating so every child has an explicit cost-appropriate model, effort, context boundary, and escalation rule.

## Route from idea to delivery

1. Read `development_workflow` status first. If none exists, resolve the workspace before starting the ledger: when Worktrunk is available, inspect its status, activate an existing branch or PR, or ask before creating a named feature branch. Otherwise confirm the effective workspace. Only then ask the user to run `/dev-workflow start <title>` or explicitly adopt existing work.
2. **Research before interviewing:** create mandatory `research.md` (`dev-workflow/research-v1`) with repository evidence, a bounded external prior-art pass by default, options, an adopt/extend/compose/build/retain recommendation, pitch implications, a simplicity check, and unknowns. External disposition is completed, not-applicable, or unavailable with its required evidence. Route a fresh Luna low Researcher for ordinary discovery and Terra low only for conflicts, provenance, or cross-boundary synthesis; Sol retains pitch synthesis. Apply the simplicity ladder before proposing new machinery: necessity → existing repository seam → standard library → native platform → installed dependency → minimum new code.
3. Grill the evidence-backed idea in repeated structured batches: identify the motivating story, desired outcome, demand, constraints, and unresolved product decisions. Never ask the user for facts the repository can answer. After each batch, summarize resolved decisions, changed assumptions, and remaining blockers before asking the next dependent batch.
4. **Set boundaries:** agree why the problem is worth the investment and a qualitative agent-investment appetite covering context surface, change depth, uncertainty allowance, validation burden, assurance level, scope cuts, stop conditions, and fixed floors. Record the mandatory wall-clock backstop separately as a circuit breaker, never as the appetite or an effort estimate.
5. **Rough out the elements:** sketch fixed product decisions, agent discretion, macro solution elements, reused seams, boundaries, flows, and observable acceptance signals without over-specifying implementation.
6. **De-risk the concept:** investigate decisive unknowns; give each rabbit hole evidence, containment, and a tripwire; cut generality; and surface decisions the user must own.
7. **Write and simplify the pitch:** create `spec.md` as a rough, solved, bounded human-agent contract. Make every section operational for the building agent. When drafting is delegated, use a fresh Sol high planner and keep product decisions with the main orchestrator; escalate to Sol xhigh only on hard-planning triggers. Run one fresh Terra-low read-only Simplifier, synthesize its delete/reuse list, apply accepted simplifications, record `pitch-simplification`, then grill the result. When confident, present the artifact and exact Refine/Approve-and-continue Question; the user's selection acts immediately.
8. **Plan and simplify the slices:** build an evolving `plan.md` and first integrated demonstrable `VS-*.md`. Read [references/slices.md](references/slices.md), preview the slice map and validation contract, and run one fresh Terra-low Simplifier before recording `plan-simplification`. When delegated, use a fresh Sol high planner, escalating to Sol xhigh only on hard-planning triggers, and make the slice executable by a Terra worker. When confident, present the artifact and exact stage Question; do not ask the user to run another command.
9. After Plan approval, execute the well-scoped slices mainly autonomously, one active slice at a time, with RED → GREEN → REFACTOR, a fresh Terra-low read-only simplification pass, and focused verification. Apply accepted deletions/reuse through the sole writer, rerun affected checks, and record slice-bound `build-simplification` before verification. Keep the main chat as orchestrator and one fresh worker as the writer: Terra medium by default, Terra high for difficult bounded implementation, and Sol medium only after the Sol planner or Oracle revalidates a sound plan whose implementation still needs frontier judgment. Never use Terra xhigh as a substitute for replanning or Sol capability. Do not add routine checkpoints. Stop only when a stated stop condition fires, product or architecture behavior needs a user decision, the approved pitch or No-Gos would change, a material rabbit hole or fixed floor is threatened, the backstop expires, or an external/destructive action needs authorization. Read [references/build.md](references/build.md).
10. Obtain independent evidence where possible, normally with one fresh Sol high reviewer per completed slice, fix accepted findings through the sole Terra writer, and rerun fresh final checks without inserting a human ceremony. Read [references/review-and-ship.md](references/review-and-ship.md).
11. Request each next transition with `development_workflow`. Discover, Pitch, and Plan each use exactly one Refine/Advance Question checkpoint; its exact result refines or advances in the same interaction. Build and Review advance autonomously from per-slice evidence. `/dev-workflow approve` is compatibility fallback only; shipping remains separately authorized.

Use [templates/spec.md](templates/spec.md), [templates/research.md](templates/research.md), [templates/plan.md](templates/plan.md), and [templates/vertical-slice.md](templates/vertical-slice.md) as starting points, not status stores. `research.md` is mandatory and the pitch must link it.

## Operating rules

- The main chat agent is the sole orchestrator and decision authority. Explicitly select every child's model and effort; never allow a delegated child to inherit the expensive Sol parent accidentally. Children return evidence and escalation requests, while the main chat synthesizes results and makes every workflow transition.
- One worker writes by default. Parallelize read-only investigation and genuinely independent review only.
- Use fresh context for scouts, researchers, planners, simplifiers, workers, and reviewers with only the stage artifact or active slice, direct contracts, fixed floors, and validation contract. Fork only the triggered Oracle whose purpose is inherited decision-consistency review.
- Use Todo only for work discovered inside the active slice. Never copy pitch, slice, phase, approval, or ledger state into Todo.
- Prefer capability checks: use Worktrunk for isolated worktrees, Question for structured ambiguity and stage decisions, LSP for code intelligence, web search for external research, GitHub for remote evidence/actions, Git conventions for commits, and pi-subagents for explicit-model scouts, researchers, planners, simplifiers, workers, reviewers, and triggered Oracle checks when available.
- Route non-trivial work through Worktrunk before starting or adopting the ledger so research evidence is born in the intended workspace. Activate existing work directly; ask before branch creation. Defer hook, routing, and removal mechanics to `pi-worktrunk`.
- With Question, shaping-stage transition input must exactly match the pending one-question Refine/Advance protocol. Accept one selection and no custom answer or note. Redirect, cancel, unavailable, malformed, and unrelated results do nothing. Without Question, `/dev-workflow approve` is the explicit compatibility fallback.
- Without Worktrunk, confirm the effective workspace and never create a hidden raw-worktree manager. Without Todo, follow the active slice sequentially and report current/next work without creating another state store.
- Without LSP, use bounded repository search plus compiler, typechecker, and test evidence, and disclose reduced semantic precision. Without web search, use repository-local evidence and state that external research was not performed; never imply current external facts were verified.
- Without Git metadata, label freshness identity unavailable. Without Git conventions, follow repository instructions and preview explicitly authorized mutations. Without GitHub tooling, give the relevant command or URL and wait for separate authorization instead of inventing a client. Without pi-subagents, the main chat plans and implements sequentially, reviews in the same context, and labels that assurance reduced.
- Apply the operating contract in [model-routing.md](references/model-routing.md) to every role: think before acting, surface assumptions and simpler interpretations, make the minimum surgical change, define verifiable success, and calibrate blockers. Complexity, uncertainty, or a failed command is not a blocker unless safe progress truly requires a user-owned decision, changed pitch, threatened fixed floor, expired backstop, or authorization.
- If pi-subagents is unavailable, the orchestrator performs the same explicit simplicity checks sequentially and records reduced assurance; never skip the Pitch, Plan, or Build simplification evidence. If any optional extension is absent, continue only through its truthful fallback; never recreate its tool.
- Never claim a commit, push, PR, merge, release, or deployment before it occurs. Remote and destructive actions require explicit user authorization.
- Appetite is a human commitment explaining why the problem deserves investment and bounding the qualitative agent envelope: context surface, change depth, uncertainty allowance, validation burden, assurance level, scope control, and fixed floors. This deliberately adapts Shape Up's fixed-time appetite for agent execution. It is not a token budget or universal complexity score. Before Pitch approval, the ledger separately requires an `Nh`, `Nd`, or `Nw` wall-clock backstop only for stale-work circuit breaking. Pausing suspends workflow mutation, not that timer.
- If a stop condition is reached or the shaped investment is exceeded before the timer, stop and ask the user to cut scope, rewind the pitch, or abandon. After a cut, request the evidence-gated Build transition; do not add another approval ceremony. Circuit commands are only for wall-clock backstop expiry; never silently expand investment, extend time, or lower fixed floors.
