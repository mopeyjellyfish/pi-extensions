# Interface craft

Read target repository instructions, observed behavior, existing UI, tokens, and
`DESIGN.md` when present. Repository instructions and verified behavior take
precedence. This catalog is for web application interfaces; it does not replace
unavailable marketing-site or native-platform expertise.

## Operation router

Route the request to one reference: `design`, `extract`, or `document` to
establish or preserve direction; `critique` or `audit` to evaluate; `polish`,
`bolder`, `quieter`, `distill`, `harden`, or `onboard` to refine; `animate`,
`colorize`, `typeset`, `layout`, `delight`, or `overdrive` to enhance; `clarify`,
`adapt`, or `optimize` to fix; and `live` to iterate with target-owned browser
evidence. Ask once only when two operations materially overlap.

“Teach the design system” routes to `document`. “Normalize” routes to `polish`
for local drift and `extract` for reusable convergence. `/shape` remains the
feature pitch lifecycle. Do not add an `init` or `craft` entry point.

Evaluation is read-only: `audit` and `critique` report evidence and propose a
follow-on operation; they do not silently fix. Bounded mechanical edits stay
direct. For behavioral implementation, delegate to `implement` or
`developing-changes` when installed; otherwise the direct parent follows target
repository guidance. This catalog does not own engineering orchestration.

Every operation must state observed evidence, the requested scope, unmet proof,
and its completion result. `live` may reuse installed browser, board, and image
evidence capabilities, but uses target-owned site commands and reports unavailable
proof honestly.
